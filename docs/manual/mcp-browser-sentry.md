# MCP browser error reporting

Task 20261012-08 is browser errors only, on the exact `https://mcp.laisky.com` origin (HTTPS and the default port). Standalone SSO, CV, chat2 and other products remain disabled. This does not instrument the Go server, MCP protocol, traces, replay, HTTP payloads or tools. The MCP Sentry project does not currently exist; creating it and approving project configuration is a separate deployment prerequisite. Never reuse the blog project's DSN.

## Deployment configuration

Vite build-time values must all be supplied explicitly by the approved deployment:

| Variable | Required value |
| --- | --- |
| `VITE_SENTRY_ENABLED` | `true` |
| `VITE_SENTRY_SITE` | `mcp` |
| `VITE_SENTRY_DSN` | Approved MCP project public browser DSN; HTTPS Sentry ingest host, 32-character hex public key, numeric project ID (1–20 digits in CI); no private key/password/query/fragment |
| `VITE_SENTRY_ENVIRONMENT` | `development`, `staging` or `production` |
| `VITE_SENTRY_RELEASE` | Exact deployed source Git SHA (7–40 lowercase hex characters); reported as `mcp@<sha>` |

Values are build-time variables, not container-runtime environment overrides of prebuilt JavaScript. The Docker frontend build accepts these five public values as build arguments. The existing CI workflow validates three public GitHub repository variables, `MCP_SENTRY_ENABLED`, `MCP_SENTRY_DSN` and `MCP_SENTRY_ENVIRONMENT`, with `.scripts/prepare_browser_sentry.py`. It derives `VITE_SENTRY_SITE=mcp` and the full `VITE_SENTRY_RELEASE` from the actual workflow `github.sha`. One preparation output supplies identical five arguments to the publishing and cache-only Docker builds. Missing/off enablement emits five blank values; explicit `true` with invalid/missing DSN, environment or full source SHA fails with a static message before either build. No actual variables or settings have been changed. Release workflow triggers, skips, needs, tags, push flags, deployment and release controls remain unchanged. The validation-only deployment-contract workflow also watches the helper and its tests so future helper-only changes run these contracts. The deployment owner must separately approve supplying the three public repository variables; adding environment variables only to the running container will not enable reporting. Never put an upload auth token in any `VITE_*` variable, source, image, environment example, or browser bundle. The public DSN is routing configuration and is intentionally browser-visible; no secret/token retrieval is required for this PR.

Missing/invalid configuration or an unsupported origin skips loading the SDK. Origin is rechecked after SDK loading, for readiness/manual capture, beforeSend and the final transport, including SDK internal event paths. Duplicate initialization is idempotent. SDK loading is bounded to three seconds; timed-out imports cannot install a late client. React root defaults remain intact when reporting is disabled or fails. SDK import/init/capture and transport failures preserve UI startup; outgoing collector requests omit credentials and referrers; diagnostics are static text and contain no exception payload or configuration. Partially installed SDK hooks cannot send errors after failed initialization.

## Privacy and diagnosis tradeoffs

Both beforeSend and a final errors-only envelope transport construct a bounded allowlist. The transport also covers SDK-internal errors that bypass beforeSend, strips envelope trace/header metadata and attachments, and drops non-error envelope types. The allowlist includes: native error types, generic error messages, fixed site/environment/release identifiers, recognized source labels, and at most four exceptions with twenty asset frames each. Stack filenames accept only the exact loaded entry module URL captured from `import.meta.url`, with the same-origin Vite `index-<8-char hash>.js` or `browser-sentry-<8-char hash>.js` shape; query strings/fragments are discarded. SDK and other unlisted chunks are omitted even if their names have a valid hash shape, preventing fabricated sensitive hashes from being forwarded. Frame function names, variables and source context are omitted. Arbitrary asset names and route URLs are omitted because they may contain user content. If bundling changes names or additional chunk symbolication is needed, extend the trusted actual-asset inventory with privacy regression coverage instead of accepting arbitrary filenames or hashes.

Requests/responses, headers/cookies, API keys/tokens, auth and local storage, prompts/completions/history, MCP arguments/results, user metadata, breadcrumbs, contexts, extra fields, fingerprints, envelope attachments and arbitrary exception messages are excluded. Strict projection intentionally sacrifices message detail and some frames. Router fallback effects report once under StrictMode. Primitive React-caught/router pairs use a 32-entry, 500ms local two-word hash cache (no raw prompt cache or emitted fingerprint); same-source and distinct errors remain reportable. Narrow-window hash collision risk can suppress a distinct paired primitive error. Primitive strings above 64KiB are dropped from manual capture to bound work and retention. Stack positions, approved asset names and release correlation remain available. No real telemetry event has been sent. Synthetic tests use a memory-only transport; they are local evidence, not project ingestion/CSP/runtime proof.
