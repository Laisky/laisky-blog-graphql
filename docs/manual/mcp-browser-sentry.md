# MCP browser error reporting

This feature reports browser errors only on the exact `https://mcp.laisky.com` origin. SSO, CV, chat2 and other origins stay disabled. It does not enable server telemetry, replay, tracing, profiling or log shipping. The pinned React SDK is 11.7.0; React19 root callbacks use its official error handler, while the router fallback covers route errors. Application modules load after optional SDK initialization; missing configuration and SDK failure preserve application startup.

## Public deployment configuration

All five Vite build values are explicit:

| Variable | Value |
| --- | --- |
| `VITE_SENTRY_ENABLED` | `true`; absent/off disables SDK loading |
| `VITE_SENTRY_SITE` | `mcp` |
| `VITE_SENTRY_DSN` | Approved MCP public browser DSN, HTTPS Sentry ingest host and numeric project ID; no private key, password, query or fragment |
| `VITE_SENTRY_ENVIRONMENT` | `development`, `staging` or `production` |
| `VITE_SENTRY_RELEASE` | Source Git SHA, reported as `mcp@<sha>` |

The existing Docker build accepts these public values as build arguments. CI validates only `MCP_SENTRY_ENABLED`, `MCP_SENTRY_DSN` and `MCP_SENTRY_ENVIRONMENT` through `.scripts/prepare_browser_sentry.py`, derives site and the actual workflow `github.sha`, and supplies identical arguments to both Docker builds. Missing/off emits blank values; explicitly enabled invalid configuration fails with a static message. No repository variables have been activated. Release triggers, skips, dependencies, tags, push flags and deploy controls are unchanged. Runtime container environment cannot change prebuilt Vite JavaScript. Never put an upload token in a `VITE_*` variable or browser bundle; the public browser DSN is intentionally visible routing configuration.

The parent created MCP JavaScript project `4512249698320384` on free Developer with its default public key enabled. Default scrubbing, IP storage prevention, the official geo rule and exact HTTPS Allowed Domains were saved. No DSN handoff or real event has occurred. Further cloud changes remain paused; this PR neither alters nor reverses settings. IP/geo retention, Allowed Domains and source fetching are optional organization policy decisions, separate from basic SDK activation. Prevent IP storage can still derive geo fields; verify processed/raw JSON if a no-geo policy is chosen. Project Verify TLS/SSL controls outbound webhooks/service hooks and also source scraping; it does not configure browser-to-Sentry TLS. No saved policy or denied action is retried here.

## Useful diagnostics and targeted privacy

The SDK uses its standard fetch transport and diagnostic default integrations. Only BrowserSession is excluded because it automatically sends session envelopes outside this errors-only feature. Default GlobalHandlers, LinkedErrors, BrowserApiErrors, Console, Breadcrumbs, HttpContext and Dedupe remain available. Ordinary error messages/types, complete stack frames/functions, lazy/vendor chunk filenames, React component stacks, technical contexts and Debug IDs are preserved. No traces sampling, replay integration or log/metric shipping is enabled.

`dataCollection` disables automatic user information, cookies, HTTP headers/bodies, URL queries, GraphQL documents/variables, AI inputs/outputs, database parameters, queue data and local frame variables. `beforeSend` also removes explicitly scoped user data, request headers/cookies/bodies, callback arguments, known credentials/prompt/history/tool payload fields, personal metadata and attachments. URL filtering removes userinfo, queries and fragments from request/stack/debug URLs and URLs embedded in retained text. Technical fields such as browser names, versions, HTTP statuses and token counts remain useful. Metadata filtering has modest traversal budgets; stack frames are retained separately without an entry-module allowlist.

Known server/tool response errors and private JSON parse failures are annotated at their actual frontend origin using weak references. The UI retains the original message and behavior; telemetry replaces only the marked private message and its linked/React/truncated copies with a fixed operation summary, preserving ordinary outer messages and stacks. The frontend reports unexpected transport, response decoding and protocol failures once with safe operation/status/code metadata. Expected authorization, validation, quota, cancellation, HTTP replies and remote MCP errors are not indiscriminately reported. Memory input validation stays a UI validation error.

Navigation, HTTP, ordinary console and useful UI breadcrumbs remain. Input/contenteditable/code/pre/private-marked DOM breadcrumbs are omitted. Known private server-error console logs retain only their fixed prefix; console argument payloads are omitted. This is targeted filtering of the application's data paths, rather than a claim that arbitrary developer-added scope content is always safe. New private request/log paths must carry the same annotations and regression coverage.

SDK loading is bounded to three seconds, with no late initialization after timeout. Configuration is validated once and snapshotted; exact origin is checked before initialization, readiness, manual/React capture and ordinary event sending. SDK failure diagnostics contain fixed text only. Object identity and SDK Dedupe prevent duplicate events; router effects are guarded under StrictMode. Primitive React/router pairs use a small 500ms cross-source hash cache, preserving independent same-source failures. Standard SDK transport owns network failures and rate limiting; outgoing collector fetches omit credentials/referrers. SDK internal diagnostics can bypass beforeSend, so application code must never put private request payloads in SDK scopes or hooks.

## Optional private source maps

Basic browser capture needs no source-map credentials. Default builds generate no maps. For a private symbolication artifact, build with `SENTRY_BUILD_PRIVATE_SOURCEMAPS=true` (a build-only value, never a Vite public variable). The pinned official Vite plugin 5.4.1 runs after React, injects Debug IDs and emits hidden maps with `sourcemaps.disable: 'disable-upload'`, `telemetry: false`, and release injection/creation/finalization disabled. This build performs no upload or release API calls, even if a token happens to exist in the inherited environment. The public runtime release remains authoritative.

The final Vite build hook checks JS/map Debug ID pairs, copies pairs and a manifest into a private temporary directory outside both the checkout and served `dist`, then removes every public map. It runs for direct Vite and package builds. Actual Vite output showed one valid map losing both ID metadata fields while its JS retained the official matching footer/runtime ID. For this measured case only, the private copy receives the two official `debug_id`/`debugId` fields derived from that verified footer. Existing mismatches are rejected; mappings, sources, public JS bytes and filenames are unchanged. The manifest records original/prepared map hashes and the repair count. A temporary root inside the checkout/dist is rejected before copying. Quarantine/validation failure aborts the build and removes only the generated maps; unrelated assets stay intact. The output directory is printed for the build owner to collect privately; it is outside the Docker `COPY web/` and `ADD . .` contexts. Do not publish this private artifact directory. Hidden map mode alone would still expose sources if maps were shipped.

Normal Docker/CI builds remain map-off: their existing build arguments do not forward the private-map flag, so those images are not claimed to contain Debug IDs or private maps. Uploading a separately rebuilt private `dist` cannot symbolize a normal image. A future owner-approved image artifact export/integration must deliver the opt-in build's exact JS and privately retain its paired maps together; that delivery work is separate from basic browser capture.

An optional later authorized stage can upload those exact paired artifacts to the MCP project using the official Sentry CLI Debug ID workflow and a narrowly scoped private credential. Never rebuild between artifact creation and upload/publication: keep the JS, maps, source SHA, Debug IDs and image digest together. Check private artifact access/content, then verify no `.map` or source content in the served artifact/image and that map URLs are unavailable. No upload credential is created/configured by this PR. Source-map upload and optional project policies are not prerequisites for initial unsymbolicated browser errors.
