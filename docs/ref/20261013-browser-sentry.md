# Browser Sentry SDK decisions (checked 2026-10-13)

- [Official React setup](https://docs.sentry.io/platforms/javascript/guides/react/) recommends instrumentation before application imports and `reactErrorHandler` for React19 root callbacks. The optional reporter loads before application modules and preserves SDK LinkedErrors/component stack enrichment.
- [SDK options](https://docs.sentry.io/platforms/javascript/guides/react/configuration/options/) documents v11 rich diagnostics, default integrations, transport and `dataCollection`. SDK11.7.0 remains pinned. Disabling automatic collection does not remove explicitly scoped user/extras, so the hooks also filter actual private categories. `enhanceFetchErrorMessages: 'report-only'` preserves UI error text. No tracing/replay/logshipping is enabled.
- [Breadcrumb integration](https://docs.sentry.io/platforms/javascript/guides/react/configuration/integrations/breadcrumbs/) and [filtering](https://docs.sentry.io/platforms/javascript/guides/react/configuration/filtering/) support useful navigation/network/console/DOM breadcrumbs with `beforeBreadcrumb` and event filtering. Pinned BrowserApiErrors can attach callback `extra.arguments`; Console formats arguments into text; LinkedErrors adds causes; exception values are truncated before beforeSend. Actual SDK envelope regressions cover these specific behaviors. BrowserSession is the sole excluded default because it emits automatic sessions outside errors-only capture.
- [Official Vite source maps](https://docs.sentry.io/platforms/javascript/guides/react/sourcemaps/uploading/vite/) places the plugin after application plugins and warns that public map files expose sources. Official pinned `@sentry/vite-plugin`5.4.1 resolves the locked `@sentry/bundler-plugins`10.76.2. Its supported `sourcemaps.disable: 'disable-upload'` option keeps Debug ID injection active with no upload; its Rollup generateBundle hook sets both map `debug_id` and `debugId`. Release inject/create/finalize and plugin telemetry are disabled. Hidden maps are quarantined outside the public build/context before publication; private upload credentials are optional and separate.
- [Sentry server-side scrubbing](https://docs.sentry.io/security-legal-pii/scrubbing/server-side-scrubbing/) explains IP prevention can still derive geo. IP/geo/origin/source-fetch settings remain optional organization policy, distinct from basic SDK activation. Saved settings are preserved; no further setting action is performed.
- [Sentry project endpoint source](https://github.com/getsentry/sentry/blob/master/src/sentry/core/endpoints/project_details.py) defines Verify SSL as certificate verification for outbound webhooks/service hooks. [Native source configuration](https://github.com/getsentry/sentry/blob/master/src/sentry/lang/native/sources.py) also applies that option to outbound source scraping. This option does not configure browser-to-Sentry HTTPS.
- [GitHub job outputs](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/pass-job-outputs) and [output parameters](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-commands#setting-an-output-parameter) support preparing validated public values once and reusing them in both Docker builds. Only the three public repository variables are accepted; site and source SHA are derived. No release controls are changed.

Measured Vite7 output had four valid flat version3 JS maps: three contained matching IDs and one lost both ID metadata fields despite one official footer/runtime UUID. The private artifact preparation follows the installed official `core/debug-id-upload.js` `setDebugIdOnSourceMap` schema for that absent-field case only, adding `debug_id` and `debugId` from the verified footer without modifying mappings, sources, public JS or asset names. Present mismatched IDs remain a failure; the manifest records original/prepared map hashes and repair count.

Current-source validation is separate from the historical candidate's earlier evidence and current runtime identity. SDK tests use synthetic in-memory envelopes; no real event, upload or cloud-settings mutation is part of this implementation. Standard SDK diagnostics are retained, and targeted hooks are not a universal transport-level privacy firewall for future arbitrary scope data.
